# Decisions

Format: date · decision · why. Spec defaults aren't repeated here, only choices the spec left open or that deviate from it.

- 2026-10-27 · **Versions: Next.js 16.4.3, next-intl 4.14.9, React 19.3.0, Tailwind 4, zod 4.6, @vis.gl/react-google-maps 1.10.1, Supabase CLI 2.122 (dev dep), pnpm 12.15, Vitest 5, Playwright 1.64.** · SPEC §3 asks to record exact versions.
- 2026-10-27 · **`cacheComponents: false`** (create-next-app 16.4 turns it on by default). · SPEC §3 describes the classic ISR model (`generateStaticParams` + `setRequestLocale` + daily `revalidate`), and next-intl's documented static setup targets that model. Cache Components would mean rewriting the data layer around `"use cache"` for no user-facing gain. Revisit when it becomes the only mode.
- 2026-10-27 · **`src/proxy.ts`** with next-intl's middleware (Next 16 renamed middleware → proxy). Matcher excludes `api`, `auth`, `_next`, `_vercel` and files with dots. · SPEC §3.
- 2026-10-27 · **Fonts: Newsreader (headings), Instrument Sans (UI), Noto Sans SC (zh, not preloaded).** Accent is ballpoint cobalt `#2A44C9`, with yellow highlighter reserved for live "here today" signals. The Work Score is drawn circled in pen; its stroke goes dashed or dotted as confidence drops. · SPEC §6 asks for an editorial "friend's notebook" look. Cobalt ink avoids the generic terracotta-on-cream look, and showing confidence in the stroke makes the honesty visible.
- 2026-10-27 · **Map placeholder is CSS graph paper**, not an SVG neighborhood outline. · SPEC §6.8 allows CSS or SVG. Graph paper costs zero bytes, fits the notebook theme, and avoids hand-drawing NYC geometry that could look wrong.
- 2026-10-27 · **Distance sort uses our own address geocoded with NYC GeoSearch** (NYC Planning Labs, open data) into `src/data/address-geo.json`. · SPEC §5.4 says the map-less list must not use Google coordinates. GeoSearch is free, keyless and NYC-specific.
- 2026-10-27 · **`data/resolve-review.md` stores only our slug and address, the chosen place ID, and match scores. It never stores Google's name or address.** · SPEC §5.3 asks for a review file, but §5.4 forbids storing Places content in the repo. Matching uses Google's text in memory only.
- 2026-10-27 · **Places SKUs:** Text Search with `id,displayName,formattedAddress` is the Pro tier, and Details with `location,businessStatus` is Pro (because of businessStatus). At ~130 spots × 4–5 runs/month we stay inside the 5k free monthly calls. The scripts print an estimate and abort above 1,000 calls per run. · CLAUDE.md rule 5.
- 2026-10-27 · **`closed?: boolean` added to the Spot schema.** · SPEC §4.2 calls it "our own closed flag"; the §4.1 type omits it.
- 2026-10-27 · **Neighborhood keys added: hudson_square, seaport, hamilton_heights, inwood, ocean_hill.** · These came up in candidate research.
- 2026-10-27 · **`profiles.hidden` column added.** · SPEC §4.4 auto-hides reported profiles but defines no column for it.
- 2026-10-27 · **Hosts auto-RSVP to their own session; "x/y going" counts RSVPs including the host.** · This is the simplest consistent reading of the capacity rule.
- 2026-10-27 · **`sessions.starts_at` gets a 5-minute grace period into the past.** · It stops clock skew from rejecting a session created "now".
- 2026-10-27 · **No local Supabase (Docker isn't installed), so E2E auth uses a second free Supabase project as the "test project".** · SPEC §10 allows either option. A second free project costs nothing and avoids installing Docker.
- 2026-10-27 · **GitHub repo under `lexioceanjoy`** (the account that is already `gh`-authenticated). · H1 was already satisfied, so nothing to ask Lexi.
- 2026-10-27 · **Google Maps terms re-checked**, current version "Last modified October 15, 2026": §14.2 still bars use with a non-Google map, §14.3 still allows caching lat/lng for 30 days, and place IDs can still be stored indefinitely. SPEC §5.4 holds unchanged. · M0 requirement. Notes in RESEARCH.md.
- 2026-10-27 · **Curated 202 candidates down to 132 to research** (see the `selected`/`curation_note` columns in `data/candidates.csv`). Dropped duplicates, single or old sources with thin work evidence, unconfirmed open status, counter-only or window-bar seating, and fourth branches of a chain. · The target is ~120 after research-stage drops; neighborhood cap 15%.
- 2026-10-27 · **Research capacity hit a session limit:** the shared web-search budget (200 calls) ran out partway through the research batches. Agents fell back to fetching pages directly, so coverage is thinner. Per SPEC §11 M1 we log the shortfall and do **not** guess. A second pass (direct fetches of venue and library sites for hours and policies) runs when capacity allows. · Data integrity over the coverage number.
- 2026-10-27 · **Place ID resolution: 123/125 spots.** Two spots got official-name query overrides (Dream Midtown, Schwarzman Building). Two more matched only weakly (Citigroup Center atrium, Greenpoint Library), so instead of forcing a match they use `fallbackLocation` from NYC GeoSearch (open data). · SPEC §5.3 says to pick a best match with a logged reason, and a wrong place ID is worse than none. The fallback is allowed by §4.1.
- 2026-10-27 · **Supabase URLs in `.env.local` had `/rest/v1/` appended** (copied from the dashboard's REST endpoint). Stripped them to the bare project URL. · supabase-js needs the base URL.
- 2026-10-27 · **`pnpm db:push [--test]`** applies migrations through the DB password, so no Supabase access token or `supabase login` is needed. · Keeps Lexi's steps minimal.
- 2026-10-27 · **Google Maps mounts in exactly one layout** (`useIsDesktop` media hook), and `reuseMaps` is dropped. · Rendering the map in both the desktop and mobile trees made two instances: each page view billed 2 map loads against the 600/day cap, and the clusterer bound to the hidden instance (no projection, so no clusters). Debugged with in-page overlay probes. Fix verified: 1 Maps JS load per view, 27 clusters.
- 2026-10-27 · **Markers kept in a ref, not React state.** · Inline ref callbacks re-run every render, and storing markers in state looped (React #185). Each marker now has a stable per-slug ref callback, and the clusterer is synced on the next animation frame.
- 2026-10-27 · **Cluster badges drawn as a pen circle with the count; the map fits all spots once on load.** · Matches the score mark, and the default zoom showed mostly New Jersey and Queens.
- 2026-10-27 · **Chinese text uses system CJK fonts (PingFang SC → Hiragino → Noto Sans CJK SC → YaHei) instead of a Noto Sans SC webfont.** · The webfont cost 20 files and 1.1 MB on zh pages plus 100 KB of @font-face CSS on every page, and pushed mobile LCP to 10s. iPhone/Mac (most 小红书 users) get PingFang, and Android gets Noto Sans CJK, the same design SPEC §6 asks for, with zero download. OG images still use a Noto Sans SC subset.
- 2026-10-27 · **Google Maps loads on first interaction on phones, on idle on desktop.** Latin webfonts use `display: optional`, and the hero's "together" is upright pen-blue with an underline (no italic font file). · Mobile Lighthouse performance went 36 → 91 (home EN), 92 (home zh), 95 (spot). SPEC §6.8 allows "on idle or on first interaction".
- 2026-10-27 · **Home list payload is a slim spot record** (no blurbs, gotchas, sources or notes). · Home HTML went 675 → 542 KB. Next lever if needed: render the list once for both layouts (it's currently server-rendered in both the desktop and mobile trees).
- 2026-10-27 · **`gh secret set NAME` reads its value from stdin; passing `--body -` stores the literal "-".** Fixed in `scripts/push-secrets.sh`. The first refresh-places run failed on it; the rerun was green. · Found from the Action log (`Invalid supabaseUrl`).
- 2026-10-27 · **Vercel env: `NEXT_PUBLIC_*` stored as config (`--no-sensitive`), everything else as encrypted secrets; the Maps key and Map ID go to Production only.** · Public vars ship to the browser by design (the anon key is RLS-guarded, the Maps key is referrer-locked). Previews run without the map, per SPEC H3.
- 2026-10-27 · **Lighthouse is judged on the median of 3 runs.** Production EN home mobile scored 87, 93 and 92 (median 92). Every other page and form factor is ≥90 on a single run, and a11y/best-practices/SEO are 100 everywhere. · Lighthouse variance is ±3–5 points.
- 2026-10-27 · **Home pages get their own OG share cards.** · The home URL is the most-shared link, and it had no preview image.
- 2026-10-28 · **Privacy page shipped as its own deploy before M3 social code; contact email is the owner address from SPEC (`site.contactEmail`).** · Google's consent screen already links to /en/privacy. The sign-in screen link and its test come with the sign-in UI in M3.
